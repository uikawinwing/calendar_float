# 月历悬浮球（Calendar Float）

Calendar Float 是用于 SillyTavern / Tavern Helper 的**世界时间可视化与提醒脚本**。

它把角色卡中分散的固定日程、剧情中动态产生的时间事项，以及当前世界时间，整理成玩家可以直接查看的月历 UI；当某个预定日期或提醒时间到达时，也可以向 LLM 提供时间提醒。

它最早用于《命定之诗与黄昏之歌》的学院与节庆日程，现在定位为可以由不同角色卡配置使用的通用 Calendar layer。

## 为什么角色卡还需要 Calendar Float

角色卡、世界书和 MVU 本身都能写下“某件事在什么时候发生”，但它们主要是文本与状态存储，不擅长处理玩家实际游玩时的时间体验。

Calendar Float 补的是这一层：

- 把分散在世界书和变量中的日期整理成统一月历，而不是要求玩家翻聊天记录找时间
- 根据角色卡自己的世界时间，而不是现实电脑日期，判断今天、即将到来与已经到达的事项
- 展示一次性、周期性、跨日期与固定世界日程
- 在预定时间或提前提醒时间到达时，向 LLM 注入简短 reminder
- 让创作者把学院课表、节庆、纪念日、比赛、船期等固定日程随角色卡一起分发
- 允许游玩过程中新增约会、截止日、临时课程等动态时间事项

Calendar Float **不负责决定剧情发生什么**。它只负责可靠地回答：

> 现在是什么时间？月历上有什么？什么东西快到了或已经到时间了？

## 产品边界

Calendar Float 不是：

- 任务管理器：任务状态、进度、目标与奖励仍属于角色卡自己的任务变量
- 新闻系统：世界新闻与传闻仍由角色卡自己的新闻变量负责
- 世界事件状态机：事件阶段、条件与后果不应存进月历
- 隐藏剧情策划器：月历不得为了填充未来日期自行创造灾害、袭击、邂逅等剧情
- 回忆或历史数据库：已经结束的剧情记录不需要由 Calendar Float 长期拥有

如果其他系统已经明确产生一个未来时间，Calendar Float 可以显示或提醒这个时间；到点只表示“时间条件成立”，最终发生什么仍由当前剧情和对应系统判断。

未来如果加入 Diary，它应该是**角色主动创作的带日期内容**，例如 NPC 写下的日记、信件或纪念记录，再由 Calendar 提供日期入口或阅读关联。Diary 属于有意义的世界内容来源，不是 Calendar 自动保存的系统历史流水账。

## 玩家得到什么

### 浮动月历 UI

玩家不用离开聊天，就能查看当前月份、每天有哪些事项、近期安排和固定世界活动。

### 世界内时间，而不是现实时间

Calendar Float 从角色卡配置的 MVU/stat_data 路径读取当前世界时间，并支持角色卡自己的纪元名、月份别名与日期格式。

如果世界时间无法解析，Calendar Float 应停止基于日期的构建，而不是偷偷使用玩家电脑的现实日期。

### 固定日程 + 动态日程

月历会合并两类主要来源：

1. **固定事项**：创作者在 `[fixed_event_index]` 中随世界书定义，例如课程、节庆、纪念日、比赛和周期活动
2. **动态事项**：剧情进行中写入 `stat_data.事件.月历` 的时间安排，例如约会、任务截止日、临时会议或追加课程

已经由固定事件索引提供的事项不需要再复制进 MVU。

### 到时提醒

动态事项可以要求 Calendar Float 在提前提醒时间或预定时间到达后向 LLM 提供 reminder。

Reminder 只传达时间事实，例如：

```text
[月历提醒]
预定事项「提交药材」的时间已经到达。
请结合当前剧情判断是否需要处理。
```

Calendar Float 不会因此自行宣布任务失败、角色赴约、灾害发生或剧情进入下一阶段。

## 动态月历变量

动态时间事项统一存放在：

```text
stat_data.事件.月历.[事件ID]
```

推荐结构：

```yaml
事件:
  月历:
    potion_deadline:
      标题: 提交药材
      内容: 公会委托的最终交付时间
      时间: 复兴纪元488年-6月20日-星期一-18:00
      提前提醒天数: 1
      标签: [任务]

    weekly_combat_class:
      标题: 魔法实战课
      时间: 每周三-14:00
      重复规则: 每周
      标签: [课程]

    private_schedule:
      标题: 后台时间事项
      时间: 复兴纪元488年-7月1日-星期五-23:00
      显示: false
      提醒: true
```

字段语义：

- `标题`：玩家或 LLM 能理解的事项名称
- `内容`：可选，只写和时间安排直接相关的简短说明
- `时间`：发生、开始或截止的世界时间
- `结束时间`：可选
- `重复规则`：可选；存在时表示周期事项
- `提前提醒天数`：可选，默认 0
- `显示`：可选，默认 `true`；只控制玩家月历 UI 是否显示
- `提醒`：可选，默认 `true`；控制是否需要在到时后提醒 LLM
- `标签`：可选，只用于 UI 分类

`显示: false` 不是隐藏剧情系统。它只代表“不在玩家月历上显示”。

## 固定事件索引

`[fixed_event_index]` 是创作者随角色卡分发的固定时间资料源，适合存放：

- 学院课程与考试日
- 节庆、纪念日与季节活动
- 固定比赛、庆典与集会
- 每年或每月重复的世界活动
- 与固定事项相关的说明条目和补充资料

索引同时可以声明该世界的 Calendar profile，例如：

```yaml
配置档案设置:
  id: generic
  显示名称: 王庭月历
  开发者模式: false
  路径:
    事件根路径: stat_data.事件.月历
    世界时间路径: stat_data.世界.时间
    世界地点路径: stat_data.世界.地点
  日期:
    纪元名: 复兴纪元
    纪元别名:
      - 复兴纪元
    中文数字年份: true
```

固定事件继续使用稳定 ID、开始/结束日期、分组、阶段、地点关键词、提醒与相关资料等结构。复杂的固定世界内容应该留在索引和正文世界书，不要复制进动态 MVU。

## 创作者工具

Calendar Float 目前包含固定事件索引编辑与世界书管理工具，用来降低角色卡作者手写大型 YAML 的成本。

主要入口：

- 主脚本：`src/calendar-float/index.ts`
- 月历 UI：`src/calendar-float/widget/`
- 固定事件索引编辑器：`src/calendar-float/fixed-event-index-editor/`
- profile：`src/calendar-float/profile/`
- runtime 世界书读取：`src/calendar-float/runtime-worldbook/`
- 世界书基础设施管理：`src/calendar-float/worldbook-manager/`
- 技术结构说明：`structure.md`

## Runtime 数据流

Calendar Float 的主流程应该保持简单：

1. 读取角色卡配置的当前世界时间
2. 读取 `[fixed_event_index]` 的固定事项
3. 读取 `stat_data.事件.月历` 的动态事项
4. 统一解析日期与重复规则
5. 合并为 Calendar dataset
6. 渲染玩家月历 UI
7. 检查即将到来或已经到达的 reminder
8. 必要时向 LLM 提供简短时间提醒

任务、新闻、世界事件和其他系统可以产生带时间的事实，但 Calendar Float 不接管它们的业务状态。

## 兼容性

重构期间仍会读取旧的：

```text
stat_data.事件.月历.临时
stat_data.事件.月历.重复
```

旧结构只用于迁移兼容。新的写入与 LLM-facing worldbook 规则统一使用单一 collection：

```text
stat_data.事件.月历.[事件ID]
```

旧的 `可见性` 只在读取旧存档时用于迁移成 `显示` / `提醒`；`类型`、`完成后`、`重要度`、`关联`、回忆与归档数据都不再属于新的 Calendar 持久化契约。
