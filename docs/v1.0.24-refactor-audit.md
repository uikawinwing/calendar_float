# v1.0.24《命定之诗》专项审计

本文件面向本仓库维护者。审计基线为 `9b8da7bb6755895d7b2d36edff147714489ade15`，发布构建为 `5ab3fc3ca55bdd1104d9428f29221b181ad05700`。仅使用 Desktop（KC-ITX-DESKTOP）上的独立同级 Worktree；未使用后续版本、CalendarCore 或 Laptop 代码。

## Stage A：审计结论

### 现有职责及应保留的实现

运行入口 `index.ts` → `profile` 初始化 → runtime/worldbook 初始化 → widget；`lifecycle.ts` 负责实例销毁。日历显示经 `storage` → `runtime-ui-dataset` / `runtime-dataset` → `calendar-view-model` → `widget/render`。Scanner 使用 `runtime-worldbook/snapshot` 聚合世界书，再交给 `runtime-trigger-evaluator`、resolver 和 Prompt 注入。

应保留：

- `date.ts`、`festival-date-range.ts` 的日期运算和固定事件范围计算；重复规则、可见性值、索引标记、宿主接口和持久化键属于程序协议。
- `event-normalizer.ts`、`runtime-dataset`、`runtime-trigger-evaluator` 的统一事件和提醒处理；不创建第二套 Core。
- 世界书 snapshot 单次读取、Scanner 的并发世代保护、widget dataset refresh queue、固定事件编辑会话的脏数据保护。
- `storage` 的 MVU 临时/重复事件读写、删除差异归档、历史记录及旧存储迁移。已有调用者的迁移层不能因名称含 legacy 就删除。
- 固定索引编辑器、关联书籍/正文阅读、世界书安装/修复/卸载，以及《命定之诗》已有的艾莉亚票券功能。

### 数据边界

| 数据 | 基线位置 | 归属与处理 |
| --- | --- | --- |
| 国家、城镇、节庆分类词与配色 | `profile/festival-visual-presets.ts` | 世界书索引的视觉规则；旧索引缺字段时保留明确的兼容默认数据 |
| 纪元与时间示例 | `profile/profiles.ts`、部分 `worldbook-manager/content.ts` | 现有 `配置档案设置.日期/世界书`；不新增配置平台 |
| 时间和地点默认路径 | profile、runtime config、生成的展示条目 | 使用同一份索引配置，修复生成条目仍用固定路径的问题 |
| 固定节庆、阶段、地点、关联资料、月份别名、提醒模板 | `节庆_索引.latest.yaml` / runtime normalizers | 已属于世界书，应保留并兼容原 YAML |
| 图标 SVG 文件与文件名解析 | `festival-icons.ts`、编辑器 icon filenames | 图标资产和安全文件名查表属于程序；选择哪个图标属于世界设定 |
| 主题、字号/尺寸、排序/过滤、提醒偏好、用户标签颜色 | widget / storage | 用户设置；不写入世界书 |
| 开发者工具开关 | profile 与 widget | 当前混合归属，需保留旧配置兼容，后续评估迁移，避免本轮改变已有工具可达性 |

### 可删除的通用化

`GENERIC_CALENDAR_PROFILE`、`CALENDAR_PROFILES` 注册表、自定义运行身份、角色/世界书检测规则、检测结果缓存及没有生产调用者的 hint 包装。运行身份固定为 fate-poem；保留路径、纪元、日期规则、世界书提示内容的可配置性。旧 `Profile: generic` 只作为旧 YAML 输入迁移，不恢复通用运行模式；陌生显式身份应诊断并拒绝索引，避免读错数据。

### 复杂度与重复

基线生产源码 31,448 行。主要文件：`widget/index.ts` 3,294 行，编辑器 `panel.ts` 1,548 行、`edit.ts` 822 行、`parse.ts` 814 行，`worldbook-manager/manager.ts` 809 行。样式文件虽大，但拆分与本轮业务边界关系不大，不做样式重写。

- widget 混合容器、偏好、编辑会话、CRUD、拖动和紧凑节庆排版。先抽出纯节庆排版计算，保留原输入输出。
- `storage/archive-actions.ts` 两处删除差异→归档/恢复循环重复，适合合并内部函数。
- Profile 和 runtime defaults 是模块全局状态；loader 只在索引带配置时更新 Profile，切到缺省/坏索引会留下旧配置，应每次从专用默认值重建。
- Scanner 一轮内已有 snapshot，不应增加第二层缓存。UI、Scanner、诊断之间的独立读取有不同生命周期；本轮不引入跨聊天共享缓存。
- UI 在显示过滤后重算提醒有语义用途，不应简单删除以减少计算。
- 当前依赖含 profile↔date 的类型引用，但不应把类型边当作运行时循环；进一步依赖检查与重构后结果在交付报告中记录。

### 已确认的原版缺陷

1. `worldbook-manager/manager.ts` 调用 `mergeManagedEntry` 却未导入，更新/修复路径可失败。
2. 编辑器将错误 YAML 转为空对象后仍可保存；已用 `固定事件: [` 复现 `canSave === true`。
3. 含高级完整逻辑的 YAML 初始不可保存，但结构化转换丢弃条件后重新变成可保存；阶段提醒的高级条件也未完整阻断。
4. 月份别名结构化修改重建对象，丢失旧对象中的扩展字段。
5. 悬浮按钮 document 释放事件 `.calendar-float-button` 未在重绑/销毁时清理。
6. 禁用的节庆/阶段提醒可能被默认文本回退再次生成，应在统一提醒计算边界阻断。
7. 世界书生成的变量展示条目仍硬编码默认根路径，和可配置更新规则不一致。

这些失败属于基线遗漏，修复需补能复现对应路径的检查，不能把原有 54 项通过视为完整验收。

## 基线验证（修改前）

- Node 24.15.0，pnpm 11.0.9；`pnpm install --frozen-lockfile` 成功，锁文件未变。
- 54/54 个 `checks/calendar-float/**/*.check.ts` 通过。
